# 06 实测方案：竞品和自研算法共用

目的有两个：

1. 用真琴和接口，公平地量出各家现成 App 的识别表现。官方的功能说明不算数。
2. 同一组测试乐句和同一批录音，以后就是自研算法的评测基准。

对应实验：`02_RISKS_AND_SPIKES.md` 的 S3（竞品）和 S2、S4（自研）。

## 1. 固定条件

每次实测前填这张表。任何一项变了，就是一次新的实测，不能和旧结果直接比。

| 项目 | 记录 |
|---|---|
| 日期 | |
| 琴（型号、被动或主动电路） | |
| 弦（型号、装了多久） | |
| 琴上旋钮（音量、Tone、拾音器） | 建议全开 |
| 线 | |
| 接口型号、增益旋钮位置（拍照） | |
| 手机型号、系统版本 | |
| 监听方式 | 接口直接监听加有线耳机 |
| 被测 App 及版本号 | |
| App 内的输入设置（选的是接口吗、灵敏度、校准值） | |
| 调音方式和结果 | 见下 |

**公平性规则**

- 同一把琴、同一套弦、同一个接口、同一个增益位置、同一天完成所有 App。
- 被测 App 的顺序随机（抓阄），避免手越弹越熟带来的偏差。
- **调音：** 先用同一个硬件调音器或固定的参考调准。再打开每个 App 自带的调音器看一眼，记下它显示的偏差。如果某个 App 要求必须用它的调音器，就按它的调，并记录这一点。
- 每个 App 都按它官方的接入说明完成设置和校准，把设置过程花的时间和遇到的问题记下来。接入折腾程度本身就是一项结果。
- 全程开手机录屏，留下每一次判定的证据。
- 不在同一天测超过三个 App，手累了数据就不可信。

## 2. 测试乐句清单

四弦标准调弦：E1（41.2 Hz）、A1（55.0 Hz）、D2（73.4 Hz）、G2（98.0 Hz）。乐句全部是原创的技术性片段，不涉及任何歌曲。

写法：“E 弦 3 品”表示最粗的弦按第 3 品。

### 2.1 正确演奏类（T）

| 编号 | 内容 | 速度 | 考察什么 |
|---|---|---|---|
| T01 | 四根空弦，每根 8 个四分音符，每个音响满 | 60 | 基本识别；最低音 E1 |
| T02 | E 弦 0、1、2、3、4、5 品，每个音 4 次 | 60 | 最低音区里相邻半音能否区分 |
| T03 | E 弦 3 品（G1，49 Hz），连续 16 次 | 60 | 调研报告里用户反映识别失败的那个音 |
| T04 | A 弦 3 品（C2），八分音符，2 小节 | 60、90、120 各一遍 | 同音连弹，数得清吗 |
| T05 | E 空弦，八分音符，2 小节 | 60、90、120 各一遍 | 最低音的同音连弹 |
| T06 | E 空弦、A 空弦、D 空弦、G 空弦，各 2 拍，**不止音**，让前面的弦继续响 | 60 | 余音重叠 |
| T07 | 同 T06，但每次换弦前**认真止住**上一根 | 60 | 和 T06 对照 |
| T08 | 八度跳：E 弦 3 品和 D 弦 5 品交替 8 次；A 弦 3 品和 G 弦 5 品交替 8 次 | 60 | 八度判定 |
| T09 | A 弦 3 品，轻拨 8 次、正常 8 次、用力 8 次 | 60 | 力度对识别的影响 |
| T10 | A 空弦，断奏，每个音尽量短，8 次 | 60 | 很短的音 |
| T11 | 左手虚按 A 弦不按实，拨 8 次（闷音） | 60 | 有起音无音高 |
| T12 | G 弦 12 品和 D 弦 12 品，各 8 次 | 60 | 高把位 |
| T13 | 根音律动：E 空弦一小节、A 空弦一小节、D 空弦一小节、A 空弦一小节，全部八分音符 | 80 | 接近真实练习的短句 |
| T14 | A 弦 3 品、D 弦 5 品、G 弦 5 品、D 弦 5 品，四分音符，循环 4 遍 | 80 | 根音、五度、八度 |

零基础阶段弹不稳是正常的。T04 和 T05 的快速度、T08、T12、T14 在阶段 0 可以先跳过，记为“尚未能演奏”，以后每过一个课程阶段补录。

### 2.2 故意出错类（X）

| 编号 | 内容 | 正确的系统应该怎样 |
|---|---|---|
| X01 | 按 T02 的谱面，但每个音都弹高一品 | 全部判错 |
| X02 | 谱面是 E 弦 3 品，实际弹 D 弦 5 品（高八度） | 判错 |
| X03 | 谱面是 A 弦 3 品，实际弹 E 弦 3 品（弦错了，品对了） | 判错 |
| X04 | 按 T13 弹，每小节故意漏掉一个音 | 漏的那个判漏弹，其余正常 |
| X05 | 按 T13 弹，每小节多弹一个音 | 多的那个判多弹 |
| X06 | 节拍器或伴奏在响，手按住所有弦，30 秒不弹 | 没有任何命中 |
| X07 | 同 X06，但手在弦上滑动、轻拍琴体、碰一下线 | 没有任何命中 |
| X08 | 按 T13 的节奏弹，但所有音都弹 E 空弦 | 该是 E 的判对，其余判错。用来检查系统是不是只听节奏不听音高 |
| X09 | 按 T01 弹，整体故意抢拍一遍、拖拍一遍 | 早晚方向报对 |
| X10 | 谱面是 E 弦 5 品，实际弹 A 空弦（同一个音，不同位置） | 只靠单路音频分不出来，判对是预期行为。记录各家实际表现 |

## 3. 三种测试方式

竞品 App 不能导入任意乐句，所以分三种方式。

### 方式 A：调音器类测试（竞品和自研都做）

打开 App 的调音器或自由识别界面。

- 逐个弹 T01、T02、T03、T12 里的每个音，各 5 次。
- 看录屏，记录：显示的音名对不对；从拨弦到显示稳定大约多久（数录屏的帧）；显示有没有在两个音之间跳。

### 方式 B：课内测试（只对竞品）

在每个 App 里各选四节最接近的课或练习：

1. 一节只弹空弦的课。
2. 一节 E 弦低品位的课。
3. 一节同音八分音符的课。
4. 一首慢速的短曲。

每节课弹四遍：

| 遍 | 怎么弹 | 看什么 |
|---|---|---|
| 一 | 认真弹对 | 弹对被判错或漏的有多少 |
| 二 | 每小节第一个音故意弹高一品，其余弹对 | 弹错被判对的有多少 |
| 三 | 完全不弹，手按住弦 | 有没有凭空得分 |
| 四 | 节奏照弹，但全部弹 E 空弦 | 系统是不是只听节奏 |

记下每个 App 选的是哪节课，以后重测用同一节。

### 方式 C：完整乐句测试（只对自研）

用 `05_LEARNING_LOOP.md` 的流程录下第 2 节的全部乐句并标注，在离线评测台上跑。到了阶段 2，再用真机实弹一遍，并做真机和离线的一致性检查（S10）。

### 可选：回放注入

把录好的干声从电脑的输出用线送进接口的输入，让手机上的 App 去听录音。好处是每家 App 听到的输入完全相同。限制是很难和 App 自己的伴奏对上拍子，所以只适合方式 A 和“等你弹对再往下走”的练习模式。阶段 0 不要求做。

## 5. 指标定义

不报一个笼统的“准确率”。分开报：

| 指标 | 算法 | 为什么单独报 |
|---|---|---|
| 弹对判错率 | 实际弹对的音里，被判成弹错或漏弹的比例（没听清另计） | 打击信心 |
| 弹错判对率 | 实际弹错的音里，被判成命中的比例 | 最危险：教会用户错的东西 |
| 凭空得分 | 不弹的测试里，每分钟出现的命中或起音数 | 应为 0 |
| 没听清率 | 所有预期音符里，被判没听清的比例 | 不能靠多报没听清来掩盖问题 |
| 起音检出率 | 实际起音里被检出的比例；另报多检的比例 | 同音连弹的关键 |
| 起音时间偏差 | 检出时刻减标注时刻，报中位数和 95 分位 | 节奏评分的基础 |
| 确认时间 | 从起音到首次给出稳定且正确的音高结论，按音高分组 | 对应反馈显示及时度 |
| 八度错误数 | 被报成高或低八度的次数 | 低音特有的问题，单独数 |

竞品只能得到前四项和主观项。自研算法要全部报告。

每项指标都按乐句类别分组，尤其要单独看 E 弦 0 到 5 品这一组。

## 6. 结论怎么写

每次实测写一份结论，放在本文件末尾的“结果”一节，格式：

1. 固定条件表。
2. 每个 App 的方式 A、B 汇总表。
3. 明确、可复现的短板清单：哪个 App、哪种乐句、失败率多少、录屏在哪。
4. 没有发现问题的地方也要写。
5. 对项目的含义：见 `02_RISKS_AND_SPIKES.md` S3 的两种结论。

**注意：** 这些结果是私人使用。如果以后要公开发表竞品对比，需要先看各家的服务条款。
