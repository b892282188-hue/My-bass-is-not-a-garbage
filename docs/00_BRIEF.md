# 00 一页定位

## 这是什么

一个和使用者一起成长的私人贝斯学习工具。

第一个用户也是现阶段唯一的用户，是产品负责人本人：零基础，没弹过任何乐器，目标是日本流行乐和爵士。他一边学琴，一边记录自己踩的坑，哪里不顺就让工具改哪里，直到贝斯入门成功。

## 两个最终目标

1. **一套自己的学习方法论。** 从真实的学习过程中提炼出来，有记录、有证据。负责人是心理学专业出身，这是他的主场。
2. **一个慢慢成型的 App。** 它是学习过程的副产品，由真实痛点一个一个推出来。

两个目标有先后：学琴第一，方法论第二，App 第三。如果现成工具已经够用，不造 App 也算成功。

## 已经确定的事

- 拾音走接线：贝斯 → 音频接口 → iPhone。麦克风拾音是以后的可选项。（ADR-001）
- 核心技术目标是低频拾音和实时反馈：音高对不对，节奏对不对。
- 开发方式：负责人不写代码。ChatGPT 调研，Claude 出方案和把关，Codex 施工。一切以 GitHub 仓库为准。
- 开发机是 Windows，没有 Mac。iOS 靠 GitHub Actions 的 macOS runner 构建。

## 明确不做的事

- 不发布，不商业化，不为“以后可能上架”做任何设计。远期是否公开，等有了真实学习成果再说。
- 不自己设计课程。用成熟课程作主干。
- 不做曲库，不碰商业歌曲的授权。
- 不做机器教师。App 不评判姿势、手型、发力、音色好坏。
- 第一版不做麦克风拾音、蓝牙耳机、软件监听和效果器、五弦和降调、MIDI 和分弦拾音。
- 不在练琴没跟上的时候继续开发。

## 成功是什么样子

- 负责人能跟着鼓稳定地弹完几首目标风格的入门曲目。
- 有一份写得出来、经得起追问的个人学习方法论。
- 如果有 App：它的每一个功能都能指到日志里的一个真实痛点，并且它的判定是可信的。

## 最大的两个风险

1. 造工具变成了逃避练琴的理由。
2. 零基础、没有真人反馈，养成坏姿势或者受伤。

对策见 `01_FEASIBILITY.md` 的 Q5 和 Q6。
