# ADR-003 引导式练习做“验证”而不是“听写”，判错必须有正面证据

- **状态：** 提议中
- **日期：** 2026-11-10
- **提出人：** 评审员（Claude）
- **确认人：** 待产品负责人确认

## 背景

引导式练习时，App 事先知道用户应该弹哪个音。利用这一点可以减少歧义、缩短窗口。但过度相信谱面，会把弹错的判成对的。

## 提议

1. 音高判定采用验证模式：把预期音和一组竞争候选（上下一到两个半音、相邻弦同品位的音、高低八度）用同一个标准打分。
2. 谱面先验只用来消解八度歧义，不用来偏袒相邻的音。
3. 判“命中”要同时满足：预期音得分比最强竞争候选高出一个余量；绝对清晰度超过阈值。
4. 并行运行一个不看谱面的自由检测器。它有把握地报出另一个音时，判“弹错”并给出那个音。
5. 判定结果为五种：命中、弹错、漏弹、多弹、没听清。
6. **判错必须有正面证据。** 拿不出“弹的是哪个音”，或者“输入健康但确实没有起音”，就只能判“没听清”。
7. “没听清”不扣分，但它的比例单独统计并设上限。
8. 测试集必须包含故意弹错和完全不弹的录音。错位谱面测试（把谱面移调后重新评，必须全部判错）进入 CI。
9. “弹错判对率”是一等指标，门槛严于“弹对判错率”。

## 理由

见 `../01_FEASIBILITY.md` Q2 的 2.3、2.4、2.6。

## 后果

- 检测器要输出置信度，不能只输出一个音名。
- 界面需要一种中性的方式显示“没听清”。
- 需要专门录一批错误演奏。
