# ADR-007 输入层抽象：判定模块只接收统一的音符事件

- **状态：** 提议中
- **日期：** 2026-11-10
- **提出人：** 评审员（Claude）
- **确认人：** 待产品负责人确认

## 背景

主路线是接线音频。麦克风是以后的可选项。远期还可能接入分弦拾音或 MIDI 设备。

## 提议

1. 定义两层抽象：
   - **音频源**：提供带采样时间戳的音频流，以及一份输入档案（路线类型、采样率、噪声底、电平、校准值）。接口和麦克风都是音频源。
   - **音符事件源**：提供统一的音符事件。字段：起音时间、音高（可空）、弦（可空）、品（可空）、力度、置信度、来源。
2. 音频路线：音频源 → 检测器 → 音符事件。MIDI 路线：MIDI 源 → 音符事件。
3. 判定、评分、界面只依赖音符事件，不知道也不关心事件来自哪条路线。
4. 检测器的阈值从输入档案取值，不写死。
5. 分析模块要能拿到“正在播放的伴奏”这一路参考信号，为麦克风路线以后做串音抑制留通路。
6. 测试集和指标按路线分开。

## 理由

现在多花很少的设计成本，以后加麦克风或 MIDI 时不用改判定和界面。

## 后果

- 第一版只实现“接口音频源”这一种，其余只有接口定义，不写实现。
- 不为还不存在的路线写任何多余代码。
