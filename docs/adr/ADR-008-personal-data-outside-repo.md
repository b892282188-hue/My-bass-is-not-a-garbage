# ADR-008 个人数据和代码分开存放

- **状态：** 已确定
- **日期：** 2026-11-10
- **提出人：** 评审员（Claude）
- **确认人：** 产品负责人（2026-11-10）

## 背景

本仓库目前是公开的。练习录音和踩坑日志属于个人数据。测试集又必须包含真实录音。

## 决定

1. 本仓库保持公开。练习录音不进任何公开仓库，存放在仓库之外的本机目录，备份到负责人的另一个 Google 账号的 Drive。目录结构和清理规则见 `../05_LEARNING_LOOP.md` 第 4.3 节。
2. 踩坑日志、周回顾、方法论卡片、录音清单和标注，放在一个私有 GitHub 仓库。
3. 本仓库的 `.gitignore` 屏蔽所有音频文件类型，只对 `tests/fixtures/real/` 开白名单。CI 检查除白名单目录以外没有音频文件被提交。
4. CI 用的小测试集：从基准乐句里挑一小批只含单音的短片段，经负责人逐个同意后放进 `tests/fixtures/real/`。负责人已同意这个做法。
5. 有版权的材料（教材内容、商业歌曲的谱面和音频）不进仓库。

## 理由

- 保护个人数据。
- 满足“测试集必须包含真实录音”，同时把公开的范围控制在负责人明确同意的最小集合。

## 公开仓库会不会被人拿走代码

负责人的顾虑：代码会不会被顺手牵羊，或者被爬虫爬走。评审员的判断是现阶段不足以顾虑，理由：

- **事实：** 公开仓库里的内容任何人都能看到和复制，爬虫和 AI 训练抓取也拦不住。这一点技术上无法防范。
- **事实：** 仓库里不放开源许可证文件时，默认保留全部权利。别人可以看，但没有合法的权利拿去用或再发布。所以本仓库**不要添加 LICENSE 文件**。
- **判断：** 这个项目真正的核心资产是负责人的踩坑日志、练习录音、标注和方法论。这些全部在私有位置，公开仓库里没有。
- **判断：** 公开仓库里现在只有文档。以后会有的检测代码，用的是公开发表的算法，本身不是秘密；它的价值来自用私有录音调出来的参数和测试集。

**复查点：** 阶段 1 开始、核心算法代码第一次进仓库之前，再问一次负责人要不要改成私有。那时改的代价很小：阶段 1 的 CI 主要跑在 Linux 和 Windows 上，私有仓库的免费额度够用；阶段 2 需要大量 macOS 构建时，负责人计划中的 Mac mini 可以当自托管的构建机，不占额度。改成私有只需要在仓库设置里点一下，随时可以做。

## 备选

- 现在就把本仓库改成私有：也可以，代价见上面的复查点。负责人选择了先保持公开。

## 后果

- 完整评测只能在负责人的 Windows 电脑上跑，CI 只跑小测试集。
- 需要一个备份习惯。
