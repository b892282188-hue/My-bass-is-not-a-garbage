# 工程规矩

适用于所有在这个仓库里工作的人和 agent。和这里冲突的做法，以这里为准。要改规矩，需要产品负责人批准。

第 1 到 8 条来自另一个项目体检得到的教训，是起点。第 9 条以后是针对本项目补充的。

## 一、仓库和流程

**1. 规格、ADR 和已确认的决定全部放在仓库里。** 不放在外部网盘、聊天记录或某个 agent 的记忆里。不在仓库里的结论不算数。

**2. 只有一条主干分支。** 功能分支要短命，合并后删除。PR 堆叠不能超过两层。agent 不直接推送主干，一律走 PR。

**3. 第一次提交就配好 CI，并且覆盖仓库里所有的平台和语言。** 现阶段只有文档，CI 就检查文档（格式、失效链接、不该出现的文件）。以后每加入一种语言或平台，同一个 PR 里必须把它接进 CI。

**4. 不允许“原型 v2、v3 并存”。** 旧原型要么合并，要么删除。一个功能在仓库里只有一份正式实现。实验代码只能放在 `experiments/`，文件开头写明过期日期，到期删除。

**5. 测试集必须包含真实录制的贝斯音频。** 不能只用合成信号去验证按合成信号写的规格。合成信号只用于单元测试里的边界情况。

**6. 文档只描述当前状态。** 历史写进 `CHANGELOG.md`。文档里不留“以前是这样、后来改成那样”的叙述，实验结果直接覆盖原来的推测。

**7. 统一用格式化工具。** 每种语言选定一个格式化工具和一份配置，CI 检查。不讨论风格。

**8. 练习录音属于个人数据，不能提交到公开仓库。** 存放位置和 `.gitignore` 见第四部分。

**9. 每个任务可追溯。** 每个 PR 对应一个任务；每个功能类任务引用至少三条踩坑日志（`05_LEARNING_LOOP.md` 第 5 节）。没有日志支撑的功能不做。地基类任务（CI、工具、文档）不受此限，但要说明为什么现在需要。

**10. 交接靠仓库，并且兼容 agent-hub。** 本仓库的决定在 `docs/adr/`，调研在 `docs/research/`，规矩在本文件。agent-hub 模板里的 `decisions/` 和 `research/` 目录在本仓库不使用；根目录的 `STATE.md` 和 `AGENTS.md` 照常使用，并在里面写明上述位置。 每个 agent 会话结束前，更新根目录的 `STATE.md`：当前阶段、进行中的事、卡住的事、下一步。下一个会话从读 `STATE.md` 和 `docs/README.md` 开始。

**11. 本地和 CI 用同一个入口命令。** 提供一个统一的检查命令（比如 `make check`），本地跑的和 CI 跑的完全一样。

**12. 密钥只放在 GitHub Secrets。** 证书、API 密钥、`.env` 文件不进仓库。

## 二、算法和测试

**13. 检测相关的改动，先过离线评测，再上真机。** 评测命令的指标表贴在 PR 里，和主干上一次的结果并排。

**14. 门槛写在仓库里，改门槛要负责人批准。** 关卡指标（`03_ROADMAP.md`）和测试阈值是受保护的。agent 不得为了让 CI 通过而调低门槛、删除或跳过测试、修改标注。确实需要改时，开任务说明原因，等负责人决定，并记入 CHANGELOG。

**15. 误收是一等指标。** “弹错判对率”和“凭空得分”必须出现在每一份评测结果里。错位谱面测试常驻 CI。

**16. 每个修掉的误判留下一个测试用例。** 真机上发现的误判，导出当时的原始输入，标注后加入测试集。

**17. 真机和离线结果必须一致。** 同一份输入录音，手机上和 Windows 评测台上的判定事件要完全相同（实验 S10）。不一致时禁止合并。

**18. 开发集和留出集按录音场次划分。** 留出集不参与调参。报告关卡指标时只用留出集。

## 三、实时音频

**19. 音频回调里不做四件事：** 不分配内存，不加锁，不读写文件或网络，不打日志。需要的缓冲在启动时一次分配好。日志通过无锁队列送到别的线程。

**20. 只有一个时钟。** 所有时间都用音频采样时间或由它换算出的系统主机时间。不用定时器驱动播放或评分，不用墙上时间。屏幕是时钟的从属。

**21. 请求值不等于实际值。** 采样率、缓冲大小、延迟，一律在音频会话激活后读实际值并记录。

**22. App 不把输入送回输出。** 第一版没有软件监听（ADR-006）。

**23. 必须能自证。** iOS 端从第一个版本起就要能导出：原始输入录音、判定事件、输入档案、音频会话的实际参数。没有这个能力，真机问题无从排查。

## 四、数据和版权

**24. 存放位置。**

| 东西 | 放哪里 |
|---|---|
| 代码、文档、ADR、原创练习谱面 | 本仓库 |
| CI 用的小批真实录音（经负责人逐个同意） | 本仓库 `tests/fixtures/real/` |
| 练习录音、基准录音 | 仓库之外的本机目录 `BassData/`，备份到负责人的另一个 Google 账号的 Drive。清理规则见 `05_LEARNING_LOOP.md` 第 4.3 节 |
| 踩坑日志、周回顾、方法论卡片、录音清单、标注 | 一个私有 GitHub 仓库 |
| 教材内容、商业歌曲的谱面和音频、别人的课程材料 | 不进任何仓库 |

**25. `.gitignore` 和 CI 把关。** 建议的忽略规则：

```gitignore
# 音频一律不进仓库
*.wav
*.aif
*.aiff
*.flac
*.mp3
*.m4a
*.ogg
*.caf
# 唯一的例外：经同意的小测试集
!tests/fixtures/real/*.wav

# 个人数据目录，防止误放
BassData/
recordings/
logs-private/

# 密钥
.env
*.p8
*.p12
*.mobileprovision
```

CI 另做一道检查：除白名单目录外出现音频文件，或白名单目录总体积超过约定上限，直接失败。

**26. 本仓库不添加开源许可证文件。** 仓库是公开的，不放 LICENSE 表示保留全部权利（理由见 ADR-008）。agent 不得顺手添加。

**27. 依赖的许可证要在白名单里。** 进入 App 的代码只用 MIT、BSD、Apache 2.0、ISC、Boost 这类宽松许可。GPL 和 AGPL 的库（比如 aubio、Essentia）只能作为离线工具单独运行，不能链接进核心库或 App。每加一个依赖，在 PR 里写明许可证和固定的版本号。

**28. 练习内容原创。** 写进仓库的练习谱面必须是原创的技术性片段，不照搬教材或课程。

## 五、给 agent 的补充

**29. 分清事实、推测和判断。** 文档和 PR 说明里，没有验证过的说法要标明是推测，并指向对应的验证实验。

**30. ADR 的状态要尊重。** “已确定”的不得推翻，只能提议。“提议中”的不能当作既定事实来施工，需要先确认。

**31. 不扩大范围。** 只做任务要求的事，不顺手重构，不顺手加功能。说不清的地方选最保守的做法，并把假设写出来。

**32. 版本要固定。** 依赖用锁文件。CI 的系统镜像和 Xcode 版本写死，升级单独开任务。

**33. 文档用中文，代码里的标识符和注释用英文。**

## 六、建议的仓库结构

等阶段 1 开始时再建。现在只有 `docs/`。

```text
README.md
STATE.md                当前状态，agent 交接用
CHANGELOG.md
docs/                   本套文档
core/                   C++ 核心库（检测和判定）
tools/                  评测程序、标注和统计脚本
ios/                    iOS 薄壳
exercises/              原创练习谱面
tests/
  fixtures/real/        经同意的小批真实录音
  fixtures/synthetic/   合成信号，只用于边界情况
experiments/            限期实验，带过期日期
.github/workflows/      CI
```
